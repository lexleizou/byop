# P15b.1 扶摇表格交互与主题修复

日期：2026-10-28。基线：BYOP 0.16.0（51e4544），本次目标：0.16.1。插件沿用 local.lightweight-table ID 和原数据目录，只调整用户可见名称为“扶摇”。

## 本次范围

修复记录选择与取消、单元格进入/退出编辑、金额展示与对齐；按新版 v4 对齐十列的显示顺序、中文分类和状态；插件主题跟随 BYOP/J Agent。保留原始真实业务数据，不做数据库迁移、自动补值或源账本写入。

## 与新版 v4 的字段对照

依据本机 `debt-ledger-v4` 源码 commit 106690e 的 `web/src/features/debts/DebtTable.tsx`、`web/src/domain/labels.ts` 与 `web/src/api/contracts.ts`，属于源码核实，不代表已验证新版 v4 线上数据库内容。

| 主表列 | 当前插件字段/处理 | 与新版 v4 的差距 |
|---|---|---|
| 债权方 | institution | 已有原始值，调整显示名称 |
| 分类 | category | 按 v4 中文分类展示，存储代码不变 |
| 产品名称 | name | 已有原始值，调整显示名称 |
| 合同本金 | principal | P15a 映射自 contract_principal_cents；不显示 CNY，右对齐 |
| 实际到账 | 当前表未导入 | 显示“未导入”，只读，不用合同本金代替 |
| 剩余应还 | 当前表未导入 | v4 来源为 principal_balance_cents，不能使用旧 amount_due 冒充 |
| 年化利率 | 当前表未导入 | 区分手动年化、计算年化与原始利率周期，未实现该模型 |
| 还款状态 | repayment_status | 未开始、还款中、逾期、已结清；未知状态保留原值 |
| 计划状态 | 当前表未导入 | 缺少本地还款计划及状态来源 |
| 下次应还 | 当前表未导入 | 缺少计划期次和金额；不将旧 date/amount 字段直接宣称为 v4 派生值 |

资金来源、原待还金额、原还款日等已有底层字段保留，不删除、不重命名业务键，不改既有 MCP 契约。当前完成展示结构对齐，不声称补齐全部 v4 数据或财务能力。

## 下一步建议：先补本地数据模型与一次性导入

仍保持独立 SQLite，不把扶摇 PostgreSQL 作为插件后端。

| 顺序 | 下一步 | 用户得到的能力 | 边界 |
|---|---|---|---|
| 1 | 明确源记录 ID 与字段映射，扩展本地字段，支持一次性导入及预览 | 实际到账、利率等有真实来源，不再只有空列 | 同名同金额的两笔记录不能靠名称猜测合并；保留源 ID；重复导入与 Agent 重试分别处理 |
| 2 | 最小还款记录、计划期次与余额计算 | 剩余应还、计划状态、下次应还有可追溯依据 | 复用 v4 已确定的本金、利息、费用、冲销口径；不直接复制完整后端 |
| 3 | 分类→产品→贷款展开，记录详情与时间线 | 同一产品的多笔贷款能区分和汇总 | 沿用行 ID，汇总行只读，操作落到具体贷款 |
| 4 | 在上述业务模型上开放 Agent 登记/修改还款与计划 | 文字操作能更新余额及日程，继续使用来源关联、防重复和撤销 | 业务操作跨表需同一事务；不能用普通字段修改替代记账 |

当前不建议同时扩大到完整仪表盘、协商、结清、提醒、文件管理等所有 v4 模块。先完成顺序 1，再以一笔贷款验证顺序 2 的闭环。文件导入可先支持一种格式，避免同时开发完整 Excel 兼容。
