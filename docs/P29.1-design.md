# P29.1 设计：输入框对齐小修（BYOP 0.22.1）

- 日期：2026-11-07
- 基线：`main` 的 `eda7a3c`（0.22.0）。不含 P30 的任何改动。
- 依据：会话工作台 `ui-audit-boardui-20261107.md` 的 A、B、C、E 四项，以及用户 2026-11-07 07:01 的要求：“把建议文字的顶边和行高对齐到输入框第一行。叠加层改用和输入框相同的起点和行高，不再在 36px 高度里居中。”
- 范围：BYOP 与 J Agent 两套外观的 Composer（`ui_v12.go` 的 `opaqueComposerV12`、`jagent_chat.go` 的 `jAgentComposerV12`）及其调用方（`chat_view.go` 的 `chatComposer`、`jagent_chat.go` 的 J Agent 版本），以及 `followup_suggestion.go` 的 `followUpGhostPlaceholder`。不改颜色、字号、动画和其它页面。

## 1. 空附件行（A）

现状：调用方总是传 `Attachments` 闭包，组件只判断 nil，没有附件时仍画出一行（下内边距 4 + 列间距 8），BYOP 卡片实测 107px（设计 96），输入框距卡片顶 24.5px（应为 12.5）。

改法：两个调用方只在 `len(s.composerAttachments) > 0` 时设置 `ComposerOptions.Attachments`；组件不变。

## 2. 建议文字对齐输入框第一行（B）

### 2.1 共同行高

新增一个函数，放在 `ui_v12.go`：

```go
// composerLineHeight is the fixed line height the composer input and its
// ghost suggestion share, so the suggestion sits on the input's first line.
func composerLineHeight(font float32) float32 { return float32(math.Round(float64(font * 20 / 14))) }
```

BYOP 正文 14px → 20px；J Agent 15px → 21px。两个 Composer 的 `TextAreaBase` 都加 `.FixedLineHeight(composerLineHeight(<输入框字号>))`。调用方之后又对 `result.Input` 设了 `FontSize`（BYOP `fontBody`，J Agent `p.bodyFont`），行高必须按同一个字号计算。输入框 `MinHeight(36)`、`Lines(1, 10)` 保持。

### 2.2 叠加层的起点

把 `TextAreaBase` 和叠加层一起放进一个包裹容器：

```go
ui.Box(c).Key("input-wrap").FillWidth().MinWidth(0).Children(func() {
    result.Input = ui.TextAreaBase(c.Key("input"), draft)...  // 原样，加 FixedLineHeight
    if empty && len(placeholderOverlays) > 0 {
        ui.Row(c).Absolute().Top(0).Left(0).Right(0).Height(lh).
            AlignItems(ui.Center).PassThrough().Children(func() {
            placeholderOverlays[0](c)
        })
    }
})
```

- 叠加层以输入框的内容左上角为起点（输入框 `Padding(0)`，所以就是包裹容器的左上角），不再用卡片内边距 `Top(12)` / `Top(p.composerPadding)` 定位。
- 叠加行高度 = `lh`（共同行高），不再是 36。
- `Key("input")` 的元素和标签 `Label(options.Label)` 不变，保证既有测试和无障碍标签可用。

### 2.3 建议行内部

`followUpGhostPlaceholder(c)` 改为接收字号与行高（或从调用处闭包传入）：

- 外层 `Row`：`Height(lh)`、`AlignItems(ui.Center)`、`Gap(8)`。
- 建议文字：字号 = 输入框字号（BYOP `fontBody`，J Agent `p.bodyFont`；现状 J Agent 也用了 `fontBody`，要改），`FixedLineHeight(lh)`，单行省略。文字盒高度等于行高，居中不产生位移。
- Tab 胶囊：保持 22px 高、圆角、边框和文字样式，在行内垂直居中（比 20px 行上下各多 1px）。

## 3. 状态行左对齐（C）

现状：`f257435` 把左边距误写成上边距（MyGo `Padding` 顺序上、右、下、左）。HUD 文字 x 比输入文字小 12.5px（BYOP）/ 11.5px（J Agent），文字还向下超出行框约 3px。

改法：

- 新增 `composerTextInset(p palette) float32`，返回卡片左内边距 + 卡片边框宽：BYOP `12 + v12BorderWidth`，J Agent `p.composerPadding + 0.5`（`jAgentGlassSurface` 的边框宽）。不要硬编码成一个数字，也不要引入新的配置项。
- 四处行元素改为 `Padding(0, 0, 0, composerTextInset(p))`：
  1. `chat_view.go` 的 `pi-hud-row`；
  2. `jagent_chat.go` 的 `pi-hud-row`；
  3. `ui_v12.go` 的 `composer-footer`（有 Footer 时）；
  4. `jagent_chat.go` 的 `composer-footer`（有 Footer 时）。
- 行高保持（HUD 20、footer 24），上边距归零，与卡片的间距靠父列已有的 `Gap(8)`。
- 没有 Footer 时那条 1px 的测试锚点行不变。

## 4. 上下文容量去重（E）

**修订（Cursor 审核 92d5002e P2-1）**：只有当 HUD 底栏项里**确实包含非空的上下文容量项**（`piHUDFooterItems()` 中的 `hudItemContextCapacity` 或对应容量项，文字非空）时，输入框配件行才不画 `composerContextChip`。HUD 行只有分支、花费、token 或插件状态而没有容量时，容量胶囊照旧显示。新增一个小函数（例如 `s.piHUDShowsContextCapacity() bool`），两套外观共用，不在各处重复判断。不改 HUD 的内容。

## 5. 版本

`mygo.json` 与 `main.go` 的 `appVersion` 都改为 `0.22.1`（`appVersion` 当前残留为 0.21.0，是 P29 漏改）。

## 6. 测试（新文件 `composer_alignment_test.go`）

每条都要对 BYOP 和 J Agent 两套外观运行，窗口 1180×760，使用既有的 `stableTestAppearance`、`layoutTestState`、`p18_2HUDState`。

1. **墨迹对齐**：同一句短文（如“帮我看看”），一次作为 ghost 建议显示（`FollowUpStyle=ghost`），一次作为 `composerDraft` 输入；在输入框左侧 48px 宽的区域内逐行找第一行和最后一行有墨迹的像素；两次的顶行之差 ≤ 1px，底行之差 ≤ 1px。参考实现（协调方的探针）见本目录 `ink_probe_reference.go.txt`。
2. **卡片高度**：无附件、空草稿时，输入框顶 − 卡片顶 = `composerTextInset(p)` ± 0.5（即卡片内边距加边框）。有一个附件时附件行存在（找得到附件名）。
3. **状态行左缘**：`p18_2HUDState` 下 HUD 文字的 x = 输入框 x ± 0.5；`run = runStreaming` 时“Pi 正在工作”（`text("chatPiWorking")`）的 x = 输入框 x ± 0.5。HUD 文字矩形完全在 `pi-hud-row` 矩形内。
4. **容量去重**（修订，P2-2）：按**完整文字精确计数**（`tt.Texts()` 中等于该容量字符串的项数），不用子串 `Find`：
   - (a) HUD 含容量（`p18_2HUDState`，胶囊走 fallback 显示 `formatContextWindow(state.hud.contextWindowFallback)`="1M"）时，独立胶囊文字出现 0 次。
   - (b) HUD 只有分支、不含容量（`layoutTestState`：已连接、分支 main、模型 GPT-5 容量 200K、`contextWindowFallback=0`）时，"200K" 出现恰好 1 次。
   - 两套外观都测；在交付说明里写明“把去重条件改回无条件绘制”与“改成 !hudVisible”两种逆向修改各自会让哪条断言失败。
5. **J Agent 建议字号**（P3-3）：建议文字的文字盒高度 = `composerLineHeight(输入框字号)` ± 0.5，并断言 J Agent 下建议文字字号与输入框一致（可用字宽：同一句短文作为建议与作为草稿的宽度差 ≤ 1px）。

既有测试必须全部通过。若有旧测试断言了旧的错误几何（如 12px 上边距），按本设计更新断言，并在交付说明里逐条列出。
