# P18.1 validation

Date: 2026-10-29. Base: `240f4d9`. App: `0.18.1`.

## Implemented

- The running-message queue is a compact, rounded group immediately above the composer with the active theme surface, border, muted text and shadow.
- Each visible item shows a branch icon, one-line ellipsized text, a compact guide affordance, remove and more controls. The existing steering/follow-up category remains available through the affordance tooltip.
- Queue ordering, the three-item display limit, overflow count, running-send modes and Pi RPC events remain unchanged.
- Per-item remove is disabled because Pi only exposes whole-queue clear; this avoids a stale local count accidentally clearing newer queued messages. The group header keeps the explicit whole-queue clear action.
- Steering items show `引导`; queued follow-ups show `排队`.
- More is disabled because the current Pi queue protocol has no per-item detail or action API.
- English and Simplified Chinese catalogs were extended for the guide affordance, two action names and unsupported-action explanation.

## Remaining bounds

- The backend exposes only `clear_queue`; this change intentionally does not add per-item remove, reorder or action endpoints.
- Disabled remove/more controls remain keyboard and pointer inert. Their explanation is exposed through the enabled wrapper because the native tooltip system suppresses tips on disabled controls.
