# BYOP P4.2 Validation

验证日期：2026-10-20

## 范围

P4.2 在 P4.1 native 生命周期基础上完成 Node runtime、类型化原生视图、插件设置注入、
插件到宿主调用和能力检查。Library、Document 与 Chat/Pi RPC 路径保持原状，WebView
仍属于 P5。

## 实现

- 宿主版本升至 `0.4.2`；navigation 可引用同一插件声明的主视图；
- Node entry 经过与 native 相同的目录包含、符号链接和普通文件检查，只接受
  `.js`、`.mjs`、`.cjs`；
- Node 使用 `--permission`，按 `files`、`network` 和 `process` 能力增加文件系统、
  网络与子进程许可；宿主缓存一次 `node --version` 探测并要求主版本不低于 25；
- JSONL JSON-RPC 支持插件发往宿主的请求与通知，保留原始 request id，并将每个进程的
  并发宿主请求限制为 8；
- 宿主实现 theme、settings、notice、task、view refresh、workspace 和文件读写调用；
  文件路径经过 workspace 包含与符号链接检查，读写上限为 1 MiB；
- 插件可通过严格类型化的 heading、text、notice、keyValue、list、code 和 button
  模型渲染主视图；未知 block 降级显示为 Unsupported block；
- 设置支持 string、number、boolean 和 select 字段，保存在
  `<configDir>/plugin-settings/<pluginId>.json`，目录权限 `0700`、文件权限 `0600`，
  使用同目录临时文件原子替换；损坏或非对象的设置文件回退到默认值，设置卡片显示
  “Settings file could not be read; defaults are in use.”，成功保存后清除警告；
- Plugins 卡片显示 runtime、能力、执行边界、宿主调用、拒绝调用、主视图入口和生命周期；
- `examples/hello-node` 是唯一新增的契约 fixture，不是功能插件。

Node 端到端测试实际调用本机 Node `v26.10.0`，未跳过。测试确认 permission model 会拒绝
插件目录和 workspace 之外的文件访问，同时完成
`initialize → activate → invokeCommand → deactivate` 生命周期。

自动测试还覆盖 manifest 视图引用与设置字段校验、Node permission flags、设置默认值合并
与 0600 文件权限、损坏设置文件回退默认值及保存后清除警告、宿主调用能力检查、路径
与符号链接越界拒绝，以及插件在 `invokeCommand` 中反向调用 `host.getTheme` 时不发生
双向 RPC 死锁。
